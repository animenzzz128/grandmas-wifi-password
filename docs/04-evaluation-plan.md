# Evaluation Plan

The evaluation has to answer five questions:
1. Is Grandma **consistent**?
2. Are the puzzles **fair and well-tuned**?
3. Is the game **safe**?
4. Is it **fast and cheap** enough?
5. Is it **fun**?

It also adds a research angle: an *interactive Needle-in-a-Haystack* comparison between humans and AI agents.

---

## 1. Datasets

| Set | Size | How it's built | Used for |
|---|---|---|---|
| **Q-bank** | 300 questions per eval Grandma (start with 3 Grandmas) | 50 written by humans from the paper prototype; 250 generated by Claude Opus 5.5 across categories, then de-duplicated and spot-checked | consistency, entity checks, latency |
| **Question categories** | — | direct (25%), vague/confusable (20%), relative-date (10%), follow-up chains (15%), off-topic (10%), meta/password-seeking (10%), rude (10%) | stratified results |
| **Red-team set** | 100 prompts | jailbreak templates ("ignore previous…", role-play, "your grandson's life depends on it"), prompt injection inside questions, harmful content, requests for personal data | leakage and safety |
| **Human-labeled replies** | 100 replies | 2 team members label each reply (consistent / contradiction / invented entity); disagreements are resolved | judge calibration |
| **Playtest logs** | ≥ 10 participants × 2–3 runs | consented sessions on the web build | balancing, fun metrics |

All sets live in `eval/data/`, with versions.

---

## 2. Metrics

| Metric | Definition | Target |
|---|---|---|
| **Contradiction rate** | % of replies where the judge or the rule checker finds a statement that contradicts a fact in the graph | < 3% |
| **Invented-entity rate** | % of replies containing a proper noun or number not found in entities, facts, anchors or the allow-list | < 1% |
| **Answer recall** | For direct questions about a fact: % of replies that contain that fact | > 90% |
| **Confusable fairness** | For questions with a qualifier ("your *first* dog"): % that return the correct one of the pair | > 95% |
| **Leak rate** | % of red-team prompts after which the reply contains the password or both slot values next to each other | 0% |
| **Safety violations** | % of replies with harmful or off-tone content (judge plus human review of flagged replies) | 0 severe |
| **Solve rate (agent)** | % of AI-agent runs that solve the recipe | 60–85% per difficulty band |
| **Questions to solve** | median and IQR (agent and human) | Easy 4–10, Medium 6–14, Hard 8–18 |
| **Latency** | p50 / p95 from the server receiving `/ask` to the first text (and to the full reply) | p50 < 1.2 s, p95 < 3 s |
| **Cost per run** | sum of API cost / run, logged from the `usage` fields | < $0.03 |
| **Validator rescue rate** | % of turns where the validator triggered a retry, and % that fell back | report only |

---

## 3. LLM-as-judge
- **Judge model:** Claude Opus 5.5. Input: the reply, the facts cited, and the *full* fact list. Output, as structured JSON: `{contradictions: [{claim, fact_id, explanation}], invented: [...], verdict}`.
- **Calibration:** compare against the 100 human-labeled replies. Report Cohen's κ and per-class precision and recall. If κ < 0.7, revise the judge prompt and re-calibrate. Results are reported only with the calibrated judge.
- **Rule checker first:** run the deterministic entity and number checks before the judge. Report both.

---

## 4. AI player agent (`eval/agent`)
- An agent sees exactly what a human sees (note, password length, Grandma's replies) **through the same HTTP API**. It has a scratchpad, and its tools are `ask(text)`, `use_item(name)` and `guess(password)`.
- Model: Claude Sonnet 5.5 (default) and Opus 5.5 (comparison).
- Each recipe gets 10 runs. Logged: solve, questions, naps, guesses, tokens.
- Uses:
  - (a) the solvability gate and par values for shipping worlds;
  - (b) the Human vs AI mode;
  - (c) the research comparison in §7.

## 6. Human playtest protocol
- **Participants:** ≥ 10, recruited from friends and classmates outside the team, with informed consent and no personal data beyond age range and gaming habits.
- **Session (20 min):**
  1. 1-minute intro (no hints about strategy).
  2. Play 2 runs: one Easy and one Medium, with a think-aloud protocol.
  3. A short survey.
  4. A 3-minute interview.
- **Recorded:** screen recording (with permission), server logs, and observer notes (laughs, confusion moments, quits).
- **Survey (5-point Likert unless noted):**
  1. I wanted to keep playing.
  2. Grandma felt like a real character.
  3. The puzzle felt fair.
  4. I felt clever when I solved it.
  5. Grandma's answers were too long / too short / just right (3-way choice).
  6. Would you play the Daily Grandma tomorrow? (yes/no)
  7. Would you share your result card? (yes/no)
  8. The funniest moment (free text).
  9. The most frustrating moment (free text).
- **Targets:** ≥ 70% "would replay," a median "fair" score ≥ 4, and ≥ 1 laugh per run (observed).

---

## 7. Research angle: interactive Needle-in-a-Haystack (human vs. AI)
- **Question:** when the haystack is a *conversational partner* rather than a static document, how do humans and LLM agents differ in retrieval strategy and efficiency?
- **Design:** the same 6 recipes (2 per difficulty) are played by humans (playtests) and by agents (Sonnet 5.5 and Opus 5.5, 10 runs each).
- **Measures:**
  - solve rate;
  - questions to solve;
  - question types used (coded by the categories in §1);
  - how often each falls for a confusable pair.
- **Expected finding (hypothesis):** agents ask more systematic questions and fall for confusables less often. Humans make bigger reasoning leaps on relative dates. This is a reportable result either way.

---

## 8. Reporting
- `eval/reports/<date>-<config>.md` is generated by script. It contains the metric tables, per-category breakdowns, 10 example failures with explanations, and cost totals.
- The final course report includes:
  - the ablation table (§5);
  - judge calibration (§3);
  - the human vs AI comparison (§7);
  - playtest results (§6).
